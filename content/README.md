# 인터뷰 글 편집 가이드

이 폴더의 파일만 고치면 사이트에 반영됩니다. **코드는 건드리지 않아도 됩니다.**

---

## 1. 새 인터뷰 올리기

`content/posts/` 안에 `.mdx` 파일을 하나 만들면 끝입니다. 목록에도, 상세 페이지에도 자동으로 나타납니다.

### 파일명이 곧 주소입니다

| 파일명 | 사이트 주소 |
|---|---|
| `kim-dohyun.mdx` | `/interviews/kim-dohyun` |
| `park-haram.mdx` | `/interviews/park-haram` |

- **영문 소문자와 하이픈(-)** 으로 지어 주세요. `김도현.mdx`처럼 한글로 지으면 주소가 깨져 보입니다.
- 띄어쓰기 대신 하이픈을 씁니다. `kim dohyun.mdx` (✗) → `kim-dohyun.mdx` (○)
- 이미 있는 파일명과 겹치면 **에러가 나면서 배포가 멈춥니다.**

### 파일 생김새

맨 위 `---` 와 `---` 사이가 **정보 칸**이고, 그 아래가 **본문**입니다.

```mdx
---
name: 김도현
role: 프리랜스 에디터 · 전 병원 홍보팀
title: 회사 밖에서 글을 쓰기까지
date: 2026-08-14
summary: 8년 다닌 병원을 나와 프리랜서로 자리 잡기까지 2년. 그 사이에 무엇을 확인했는지 물었다.
tags: [전직, 독립]
pullQuote: 그만두는 건 결정이 아니라 과정이었어요.
---

<QA q="그만두기로 마음먹은 결정적인 순간이 있었나요?">
없었어요. 그게 제일 말하고 싶은 부분이에요.
</QA>
```

가장 쉬운 방법은 **기존 파일을 복사해서 내용만 바꾸는 것**입니다.

## 2. 정보 칸 — 각 항목의 뜻

| 항목 | 꼭 필요? | 어디에 보이나 | 설명 |
|---|:--:|---|---|
| `name` | **필수** | 마퀴 · 목록 · 상세 | 인터뷰한 사람의 이름 |
| `role` | 선택 | 마퀴 · 목록 · 상세 | 직업이나 소속. **비우면 그 줄만 조용히 사라집니다** |
| `avatar` | 선택 | 마퀴 · 목록 · 상세 | 사진 경로. 비우면 이름 첫 글자가 동그라미로 나옵니다 |
| `title` | **필수** | 목록 · 상세 제목 · 브라우저 탭 | 인터뷰 제목. 30자 이내를 권합니다 |
| `date` | **필수** | 목록 · 상세 · 정렬 | 인터뷰 날짜. **`2026-08-14` 형식** |
| `summary` | **필수** | 상세 첫 문단 · 검색결과 설명 | 120자 이내 권장. **목록 카드에는 안 보입니다** |
| `tags` | **필수** | 목록 · 상세 뱃지 | 1~4개 |
| `pullQuote` | 선택 | 마퀴 카드 | 대표 문장. 40자 이내. 비우면 `summary` 앞부분이 대신 쓰입니다 |
| `published` | 선택 | — | `false`로 적으면 사이트에서 감춰집니다. 안 적으면 공개 |

### `date` — 가장 실수가 잦은 항목

**반드시 `연도-월-일` 네자리-두자리-두자리**로 적습니다.

| 이렇게 | 결과 |
|---|---|
| `date: 2026-08-14` | ○ |
| `date: "2026-08-14"` | ○ (따옴표 있어도 됩니다) |
| `date: 2026-8-14` | ✗ 월·일은 두 자리로. `08`, `04`처럼 앞에 0을 붙입니다 |
| `date: 2026.08.14` | ✗ 점이 아니라 하이픈입니다 |
| `date: 2026-02-31` | ✗ 없는 날짜입니다 |

목록은 이 날짜를 기준으로 **최신순**으로 정렬됩니다.

### `tags` — 태그

**정해진 목록이 없습니다.** 필요한 단어를 그냥 쓰시면 됩니다.

```yaml
tags: [전직, 독립]
tags: [다시공부, 공백기]
tags: [내가방금만든태그]     # 이것도 됩니다
```

| 규칙 | 설명 |
|---|---|
| 개수 | **1개 이상 4개 이하.** 5개부터는 에러입니다 (카드 모양이 깨져서) |
| 길이 | 태그 하나가 1~20자 |
| 중복 | 같은 글 안에서 같은 태그를 두 번 쓰면 에러 |
| 공백·`#` | 앞뒤 공백과 맨 앞 `#`은 **자동으로 지워집니다.** `"# 전직"` → `전직` (단 `#`을 쓰려면 큰따옴표가 필요합니다 — 7번 항목 참고) |

태그는 **보여주기 전용**입니다. 눌러도 아무 일도 일어나지 않습니다. (태그별 페이지나 검색 기능은 없습니다.)

> **오타 주의**
> 사이트 전체에서 딱 한 번만 쓰인 태그가 있으면, 배포할 때 이런 안내가 나옵니다:
> ```
> ⚠ 한 번만 사용된 태그가 있습니다. 오타가 아닌지 확인해 주세요:
>    - 전 직   (park-haram.mdx)
> ```
> `전직`을 `전 직`으로 잘못 쓴 걸 잡아 주는 장치입니다.
> **배포가 멈추지는 않습니다.** 새 태그를 처음 쓸 때도 나오니, 확인만 해 주세요.

### `avatar` — 사진 넣기

1. 사진 파일을 `public/avatars/` 폴더에 넣습니다. (예: `kim-dohyun.jpg`)
2. 정보 칸에 경로를 적습니다:

```yaml
avatar: /avatars/kim-dohyun.jpg
```

`public`은 경로에 **쓰지 않습니다.** `/avatars/`부터 적습니다.

사진이 없으면 이 줄을 아예 **빼세요.** 그러면 이름 첫 글자가 동그라미로 들어갑니다.

## 3. 본문 — 질문과 답변 쓰기

질문 하나와 답변 하나를 `<QA>` 로 묶습니다.

```mdx
<QA q="여기에 질문을 적습니다">
여기에 답변을 적습니다.

빈 줄을 하나 넣으면 문단이 나뉩니다.
</QA>
```

- 질문은 `q="..."` **큰따옴표 안에** 적습니다.
- 답변은 `<QA>` 와 `</QA>` **사이에** 적습니다.
- `<QA>` 묶음을 원하는 만큼 이어 붙이면 됩니다. 적은 순서대로 나옵니다.
- 묶음과 묶음 사이에는 빈 줄을 한 줄 넣어 주세요.

> **질문에 큰따옴표를 쓰고 싶다면**
> `q="그는 "왜"라고 물었다"` 처럼 쓰면 따옴표가 엉킵니다.
> 작은따옴표를 쓰거나(`q="그는 '왜'라고 물었다"`) 홑낫표(`「 」`)를 쓰세요.

---

## 4. 글을 잠시 감추고 싶을 때

파일을 지우지 말고 `published: false` 한 줄을 넣으세요.

```yaml
published: false
```

목록에서도 빠지고 주소로 직접 들어가도 "찾는 인터뷰가 없습니다" 화면이 나옵니다.
다시 공개할 때는 `true`로 바꾸거나 그 줄을 지우면 됩니다.

## 5. 태그 순서 정하기 (선택)

`content/tags.json` 에서 뱃지가 보이는 순서를 지정할 수 있습니다.

```json
{ "order": ["전직", "다시공부", "공백기", "독립"] }
```

- 여기 **적힌 태그가 적힌 순서대로** 먼저 나옵니다.
- 여기 없는 태그는 **많이 쓰인 순서 → 가나다순**으로 그 뒤에 붙습니다.
- **이 파일은 없어도 됩니다.** 없으면 전부 자동 순서로 나옵니다.
- 여기에 태그를 적었다고 그 태그가 생기는 건 아닙니다. 태그는 어디까지나 각 글의 `tags`에서 만들어집니다.

## 7. 에러가 났을 때

정보 칸에 문제가 있으면 **배포가 중간에 멈추고**, 어느 파일의 어느 항목이 문제인지 알려 줍니다.

```
content/posts/kim-dohyun.mdx: frontmatter 검증 실패
  - date: YYYY-MM-DD 형식의 실제 날짜여야 합니다 (받은 값: "2026-8-14")
```

`파일 이름` → `문제가 있는 항목` → `무엇이 잘못됐는지` 순서로 읽으시면 됩니다.

### 자주 나오는 메시지

| 메시지 | 뜻과 해결 |
|---|---|
| `date: YYYY-MM-DD 형식의 실제 날짜여야 합니다` | 날짜 형식을 `2026-08-14`처럼 고칩니다 |
| `title은 필수입니다` | `title:` 줄이 빠졌거나 비어 있습니다 |
| `태그는 최대 4개까지만 쓸 수 있습니다` | 태그를 4개 이하로 줄입니다 |
| `태그를 최소 1개 적어 주세요` | `tags:` 가 비어 있습니다 |
| `같은 글 안에서 태그가 중복됐습니다` | 같은 태그를 두 번 썼습니다 |
| `slug가 중복됐습니다` | 파일명이 겹칩니다. 하나를 다른 이름으로 바꿉니다 |

### 값에 `:` 이 들어갈 때 — 에러가 납니다

```yaml
title: 회사: 밖에서 글을 쓰기까지     # ✗ 배포가 멈춥니다
title: "회사: 밖에서 글을 쓰기까지"   # ○ 큰따옴표로 감싸면 됩니다
```

이 경우는 위와 다른 모양의 메시지가 나옵니다 (`bad indentation of a mapping entry` 등). 에러가 나니 **그나마 바로 알 수 있습니다.**

### ⚠ 값에 `#` 이 들어갈 때 — 에러 없이 **조용히 잘립니다**

이게 제일 위험합니다. **아무 경고도 없이 글자가 사라집니다.**

```yaml
summary: 요약입니다 #1번은 아니었어요
```

이렇게 쓰면 `summary` 가 **`"요약입니다"`** 로 저장됩니다. `#` 부터 뒤가 통째로 날아갑니다.

```yaml
pullQuote: #1번은 아니었어요
```

이건 `pullQuote` 가 **통째로 비어 버립니다.**

**띄어쓰기 뒤에 `#` 이 오면 큰따옴표로 감싸 주세요.**

```yaml
summary: "요약입니다 #1번은 아니었어요"   # ○
pullQuote: "#1번은 아니었어요"            # ○
```

> 붙여 쓴 `#` 은 괜찮습니다. `pullQuote: 해시태그#1을 썼다` 는 그대로 나옵니다.
> 문제가 되는 건 **`#` 앞에 띄어쓰기가 있을 때**입니다.

태그도 마찬가지라, `#` 을 붙여 쓰고 싶으면 따옴표가 필요합니다.

```yaml
tags: ["# 전직"]     # ○ → 자동으로 "전직" 이 됩니다
tags: [# 전직]       # ✗ 에러가 납니다
tags: [전직]         # ○ 그냥 이렇게 쓰는 게 제일 깔끔합니다
```

### 그 밖의 체크리스트

- `---` 줄이 위아래로 **각각 하나씩** 있는지
- 들여쓰기에 **탭 대신 공백**을 썼는지 (탭을 쓰면 에러가 납니다)
- `<QA>` 를 열었으면 `</QA>` 로 **닫았는지**
- 값이 길어져도 **한 줄에** 이어서 쓰는지 (줄을 바꾸려면 큰따옴표로 감싸세요)

## 8. 요약

```
content/
├─ README.md          ← 지금 읽고 계신 문서
├─ tags.json          ← 태그 순서 (선택)
└─ posts/
   ├─ kim-dohyun.mdx  ← 인터뷰 1명 = 파일 1개
   ├─ lee-seojin.mdx
   └─ park-haram.mdx

public/avatars/       ← 사진은 여기에
```

기억할 것은 세 가지입니다.

1. **파일 1개 = 인터뷰 대상 1명**, 파일명이 곧 주소
2. `name` · `title` · `date` · `summary` · `tags` 는 **반드시** 적기
3. 에러 메시지는 **파일 이름과 항목 이름**을 알려주니 그 줄만 고치면 됩니다
